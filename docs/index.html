    /how-it-works

    Propose, decide, prove, verify

    The model only suggests. Plain Rust decides. The receipt proves which code made the call, and every decision commits the state before and after it, so the receipts form a chain.

    01 · propose

    The agent asks

    An agent sends a payment proposal: recipient, amount, time and a memo. It cannot approve anything itself.

    02 · decide

    The policy rules

    A small Rust program checks the allowlist, a per-transfer cap, a daily limit and a minimum gap, then answers APPROVE or REJECT with a reason.

    03 · prove

    The zkVM proves it

    The policy runs inside the RISC Zero zkVM. The receipt is tied to the program's image ID, so changing one line of the policy changes the ID.

    04 · verify

    zkVerify checks it

    zkVerify verifies the Risc0 proof natively, without wrapping it in Groth16, and records it on-chain. Each decision gets a finalized transaction.

    the rules that decide · methods/guest/src/main.rs 
    let reason = if amount == 0 { ZERO_AMOUNT }
else if seq > 0 && ts < last_ts { CLOCK_WENT_BACKWARDS }
else if !allowlist.iter().any(|a| a.to_lowercase() == rcpt) { RECIPIENT_NOT_ALLOWLISTED }
else if amount > max_per_transfer { OVER_PER_TRANSFER_CAP }
else if spent_base.saturating_add(amount) > daily_limit { OVER_DAILY_LIMIT }
else if seq > 0 && ts.saturating_sub(last_ts) < min_gap_secs { TOO_SOON_AFTER_LAST }
else { OK };
// journal (public): policy hash · proposal hash · state before · state after · decision · reason · seq

    Check it in your browser

    This decodes each public journal and recomputes every hash it commits to (the policy, the proposal, the state before and after) from the published demo files, then checks the chain. Your browser doesn't re-run the STARK verifier; zkVerify did that, and each transaction above links to it.

      /why-zkverify

      Why zkVerify carries this

      native zkVM verification

      The receipt goes in as it is

      zkVerify verifies RISC Zero STARK proofs natively. On an EVM chain the same receipt first has to be wrapped into a Groth16 proof, an extra proving step the zkVerify docs say adds a lot of latency. Here the receipt is submitted directly through Kurier and comes back finalized.

      what I found building it

      Version matters

      zkVerify's Risc0 verifier has contexts up to v3.0. Receipts from risc0 3.1 failed it (control_id mismatch). Every risc0 2.x and 3.0 crate is yanked on crates.io, so the build pins 2.3.2, the release that fixed CVE-2025-61588, through the lockfile. tools/zkv-check runs zkVerify's own verifier locally before anything is submitted.

      /run-it

      Run it yourself

      Linux or WSL, Rust, the RISC Zero 2.3.2 toolchain and Node 20+. Proving takes about 2 to 4 minutes per decision on a laptop CPU.

      1. Install the toolchain

        curl -L https://risczero.com/install | bash
rzup install cargo-risczero 2.3.2 && rzup install r0vm 2.3.2

      2. Prove the five decisions

        Real proofs, no dev mode. Each run starts from the state the previous one ended on. Your proofs go to myruns/, so the committed runs/ stay exactly as submitted.

        git clone https://github.com/ibnweb3/policy-replay && cd policy-replay
bash scripts/run-demo.sh

      3. Submit to zkVerify and check the chain

        Needs a Kurier testnet API key in .env as KURIER_API_KEY.

        for r in myruns/*; do node scripts/submit.mjs "$r"; done
node scripts/check-chain.mjs myruns
      /limits

      What it does not do

      • It proves the decision followed the policy, given the inputs. It doesn't prove the proposal was sensible, or that a payment was then made on a payment rail. Tying execution to the receipt is the next step.
      • It isn't real-time. 2 to 4 minutes of CPU proving per decision suits an audit trail, not gating a checkout.
      • The policy is small on purpose: allowlist, per-transfer cap, daily limit, minimum gap.
      • The chain catches edits and gaps in the middle. Entries cut off the end need the latest state hash published somewhere else.
      • Testnet only. All five receipts are on zkVerify's Volta testnet.
